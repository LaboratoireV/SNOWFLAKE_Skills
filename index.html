ONE WAREHOUSE, ONE QUESTION

-- Monthly revenue with a running total
USE WAREHOUSE lab_wh;

SELECT region,
       DATE_TRUNC('month', order_date) AS month,
       SUM(amount) AS revenue,
       SUM(SUM(amount)) OVER (
         PARTITION BY region ORDER BY month
       ) AS running_revenue
FROM lab_db.retail.orders
GROUP BY region, month;

Key concepts

Four layers between a question and an answer.

Each layer has a distinct job. Knowing where work happens makes queries easier to tune, secure and pay for.

  1. 01 Storage Compressed, columnar tables
  2. 02 Warehouse Compute that runs the query
  3. 03 Services Optimizer, metadata, security
  4. 04 Results Snowsight, BI tools, Python
S|C

Storage and compute are separate

Data is stored once, while any number of virtual warehouses can query it independently, so heavy jobs need not slow everyone else down.

XS

Pay for what runs

Warehouses can suspend when idle and resume on demand. Sizing for the real bottleneck matters more than choosing the biggest size.

⟲

Time Travel

Query or restore data as it was earlier, within a retention window, which turns many mistakes into recoverable ones.

⧉

Zero-copy cloning

Clone a table, schema or database for testing without duplicating storage until the copy starts to change.
